# Utils Rules

## pipeline.py — PipelineBlock / Pipeline
- `PipelineBlock[I, O]` is a stage with `Queue[I] -> Queue[O]` semantics; queues are assigned by `Pipeline` at wiring time, never created by blocks themselves.
- Build blocks only via the factory classmethods (decorator turns the function into a block instance at import time, same dialect as `MessageCommand`):
  - `@PipelineBlock.from_map(separate_process=...)` — element-wise function `I -> O` (sync or async).
  - `@PipelineBlock.from_consumer(separate_process=...)` — self-managed sync loop function `(input_queue, output_queue) -> None`. Named `from_consumer` (over `from_handler`/`from_sink`) because the wrapped function consumes the input stream itself; it receives both endpoints because `Pipeline` wires the output queue before start.
- Consumer functions MUST exit when receiving `PIPELINE_STOP` and forward it to their output queue — sentinel shutdown relies on it.
- Sentinel comparison must be `!=` / `==`, never `is`/`is not`: pickling through a queue yields a non-identical object.
- Execution modes: `separate_process=True` → dedicated `multiprocessing.Process` (heavy stages: STT, TTS); async `from_map` in-process → `asyncio` task on the caller's running loop (blocking `queue.get` wrapped in `run_in_executor`, so shared loop-bound clients like `AsyncOpenAI` stay usable); everything else in-process → daemon `threading.Thread`. The wrapped function must be defined at module level.
- `Pipeline(*blocks)` wires adjacent blocks with `multiprocessing.Queue` buffers; `pipeline.input` / `pipeline.output` are the head/tail queues for producers/consumers. Lifecycle matches routers: `await pipeline.start()` spawns all stages; `await pipeline.stop()` sends `PIPELINE_STOP` from the head, awaits async tasks and joins processes. There is no separate `join()`.
- Intended usage: spawn inside a server-level router's `async def start()` / `async def stop()`.
## Local speech stages (discord_bot/routers/discord_agent/utils)
- `voice_agent/` subpackage holds the voice pipeline stages and their assembly (`build_voice_pipeline`): ASR → Gatekeeper → Agent → TTS with `LockStarted`/`LockEnded` markers and `ConversationWindow` (anchor = last released record + bot reply; prefix = passed phrases of the current lock; `agent_busy` acts as a lock). Gatekeeper/Agent are async consumers on the router loop sharing the window object — they MUST stay in-process; consumers may absorb items (gate drops denied phrases). Whisper-tiny garbles morphology on short synthetic/short phrases ("женя ты" → "Женят и"); the gate prompt explicitly instructs intent-over-spelling because of this.
- `SpeechRecognizer` (ASR, thread stage): `transcribe(pcm_16bit_bytes, sample_rate) -> str`. faster-whisper `tiny` int8, beam/best 3, built-in Silero VAD (`vad_filter=True`), RU language, resamples any input rate to 16 kHz via `scipy.signal.resample_poly`. Weights: `PRELOADED_BINARIES_FOLDER / whisper-tiny`.
- `SpeechSynthesizer` (TTS, process stage): `synthesize(text: str) -> bytes` (16-bit PCM mono, 48 kHz). Silero TTS v5 checkpoint (`PRELOADED_BINARIES_FOLDER / silero-tts / v5_ru.pt`), baya voice, torch CPU-only + `inference_mode`. Latin words/phrases are replaced with Russian transcriptions via `ru-normalizr` (`NormalizeOptions.tts()`) before synthesis (`_russify`).
- Model weights live in `preloaded_binaries/` (LFS-tracked, path from `globals.PRELOADED_BINARIES_FOLDER`); see that folder's README.
- `DecisionSession` (gatekeeper): async Decisions-API driver (`POST /api/alpha/decisions`, NOT chat completions). It derives an origin-scoped OpenAI client from the `LLMSession` cache (the SDK concatenates paths onto `base_url`, so `/api/alpha/decisions` needs the bare origin) and uses `client.post(..., cast_to=object)`. `decide(state, questions) -> dict[str, DecisionAnswer]`.
- Gatekeeper state (span-01, verified by A/B in `[dev]voice_assistant_research/results/shape_ab_results.json`): `input` = system identity message ("You are {bot}... It is you: assistant-role turns are your own replies") + anchor turns (real `user`/`assistant` roles) + prefix; `output` = judged phrase (role `assistant` — API requirement). Bare `{input, output}` without the identity message cannot judge follow-up commands (noul ~0.07); the identity message costs ~2pp clean accuracy but is the only shape where follow-ups work and gains ~5pp on noisy STT. The question tells the model the transcript is raw ASR output with recognition errors (judge intent, not spelling) — restrictive spelling-based criteria + ASR errors misclassify garbled vocatives. Threshold in code: **0.60** for noisy ASR channels (0.50 only for clean text), never in the prompt.
